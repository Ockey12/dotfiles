# HTML Report

どのレポートも同じ見た目と同じ構成になることを最優先する。CSSは`assets/template.html`にだけ存在し、エージェントは本文のHTML断片だけを書く。断片は`scripts/build.py`が検査してテンプレートへ流し込むため、デザインを毎回考えたり、CSSを書いたりしない。

## ファイル構成

パスはこのスキルのディレクトリを基準とする。

- `SKILL.md`: 手順と構成のルール
- `references/components.md`: 使えるコンポーネントと、その正確なマークアップ
- `assets/template.html`: CSSを含むページの雛形。編集しない
- `scripts/build.py`: 本文断片を検査し、テンプレートへ流し込んでレポートを出力する
- `examples/observation-migration.body.html`: 本文断片の完成例

## 手順

1. `references/components.md`を最後まで読む。
2. 下記の「構成」と「書き方」に従って本文断片を書き、一時ディレクトリに保存する。構成に迷ったら`examples/observation-migration.body.html`を読む。
3. ビルドする。

   ```bash
   python3 <このスキルのディレクトリ>/scripts/build.py <本文断片.html> -o <出力先.html>
   ```

4. 検査エラーが出たら、表示された行番号の箇所を直して再実行する。エラーがある間はレポートが出力されない。警告は構成ルールからの逸脱を示すため、意図したもの以外は直す。
5. macOSでは`open <出力先.html>`で既定のブラウザに表示する。
6. ユーザーへの応答では、出力したファイルの絶対パスと、レポートの要約を数行で返す。レポートの全文をチャットに貼らない。

成果物はローカルのHTMLファイルである。Webへの公開や共有用のホスティングは、ユーザーが求めた場合だけ行う。

## 保存先

ユーザーが保存先を指定しなければ、`~/Documents/AIReports/YYYY-MM-DD-<slug>.html`に保存する。`<slug>`は内容を表す短い英語のケバブケース(例: `observation-migration`)にする。同名のファイルがあれば`-2`、`-3`と連番を付け、既存のレポートを上書きしない。

## 修正の依頼

既存のレポートを直すときは、出力したHTMLファイルの本文(`<!-- report:body:start -->`と`<!-- report:body:end -->`の間)を直接編集し、同じファイルを入力と出力に指定して再ビルドする。目次とidは再生成される。

```bash
python3 <このスキルのディレクトリ>/scripts/build.py <レポート.html> -o <レポート.html>
```

## 構成

本文は次の順に並べる。

1. ページヘッダー: アイコン、タイトル、プロパティ(作成日、種類、対象、ステータス)
2. 要約: 灰色のコールアウト。最初の段落は「結論: 」から始める
3. 目次: `<h2>`が4つ以上あれば自動で入る
4. 本文のセクション(`<h2>`)
5. 参考資料: 出典がある場合だけ、最後のセクションに置く

セクションは、レポートの種類に応じて次の並びを基本とする。内容に合わない見出しは省き、足りない見出しだけを追加する。

| 種類 | セクションの並び |
| --- | --- |
| 調査 | 背景と目的、調査結果、考察、次のアクション、参考資料 |
| 比較 | 比較の観点、比較表、各案の詳細、推奨、参考資料 |
| 障害調査 | 現象、原因、対応、再発防止、参考資料 |
| 設計 | 目的と制約、設計案、検討した代替案、未解決の課題、参考資料 |
| まとめ | 内容に応じた見出し、次のアクション |

## 書き方

- 結論を先に書き、根拠をその後に書く。要約だけを読めば結論と次の行動が分かるようにする。
- 1段落には1つの論点だけを書く。3つ以上の項目を2つ以上の観点で比べる内容は表にする。
- 日本語の文章は常体(だ・である調)で書き、`japanese-writing-rules`スキルの表記ルールに従う。特に、日本語と英数字やコードの間に空白を入れない。丸括弧は半角にする。
- 太字などの強調は使わない(`<strong>`や`<b>`は検査でエラーになる)。重要な内容は、コールアウト、見出し、文の順序で示す。
- 絵文字はページアイコンにだけ使う。見出しや本文には書かない。状態や評価はタグで示す。
- 事実には出典を付ける。出典のURLは、実際に読んだページだけにする。推測は推測と分かるように書く。
- 本文に載せきれない詳細(長いログ、全件のデータ)はトグルに入れる。

## 禁止事項

- `assets/template.html`のCSSを編集したり、レポートごとにCSSやJavaScriptを追加したりする
- `references/components.md`にない要素、class、`style`属性を使う
- `scripts/build.py`を通さずにHTMLファイルを書く
