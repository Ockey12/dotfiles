ObservableObjectから@Observableへの移行調査

作成日
2026-11-05
種類
調査
対象
SwiftUIアプリの状態管理(Appleのサンプル「BookReader」相当の構成)
ステータス
完了

結論: 最小対応OSがiOS 17以降なら、モデル型を1つずつ@Observableへ移行できる。ObservableObjectと混在させたまま進められるため、一括で置き換える必要はない。

  • 移行後のViewは、bodyで読んだプロパティが変わったときだけ更新される
  • 主な作業は、@Publishedの削除と、@StateObjectなどのプロパティラッパーの置き換えである
  • iOS 16以前もサポートする場合は、Perceptionライブラリで同じ書き方を先に導入できる

背景と目的

このアプリは、CombineのObservableObjectと@Publishedでモデルの状態を管理している。iOS 17以降のSwiftUIは、Swiftの言語機能として実装されたObservationフレームワークに対応している[1]。

本レポートでは、Observationへ移行する価値、移行の手順、移行中の注意点を整理する。

調査結果

更新の仕組みの違い

最も大きな違いは、Viewが更新される条件である。ObservableObjectでは、Viewが読んでいないプロパティでも、いずれかの@Publishedプロパティが変わるとViewが更新される。@Observableでは、Viewのbodyが直接読んだプロパティが変わったときだけ更新される[1]。

観点ObservableObject@Observable
提供元CombineObservation(Swift 5.9)
変更を通知するプロパティ@Publishedを付けたものすべて(除外するものに@ObservationIgnoredを付ける)
Viewが更新される条件いずれかの@Publishedが変わったときbodyで読んだプロパティが変わったとき
オプショナルやコレクション内のオブジェクト追跡できない追跡できる
対応OSiOS 13以降iOS 17以降

プロパティラッパーの対応

データフローのプロパティラッパーは、次のように置き換える[1]。

用途移行前移行後
Viewがモデルを所有する@StateObject@State
環境へモデルを渡す.environmentObject(_:).environment(_:)
環境からモデルを取り出す@EnvironmentObject@Environment(Library.self)
モデルを受け取って表示する@ObservedObject通常のプロパティ
モデルのプロパティへのバインディングが必要@ObservedObject@Bindable

移行する利点

  • Viewが読んでいないプロパティの変更で再描画されなくなる
  • @Publishedを付け忘れる誤りがなくなる
  • @Stateや@Environmentなど、値型と同じ仕組みでモデルを扱える

移行で気をつけること

  • 最小対応OSがiOS 17以降になる
  • Combineの$付きのPublisherで購読している箇所は書き換えが必要になる
  • 移行中は、型ごとにViewの更新条件が異なる

移行手順

Appleの移行ガイドは、次の順に進める方法を示している[1]。

  1. モデル型のObservableObjectへの準拠を外し、@Observableマクロを付ける
  2. @Publishedを外す。Viewから読めるが追跡したくないプロパティには@ObservationIgnoredを付ける
  3. @StateObjectを@Stateに、.environmentObject(_:)を.environment(_:)に置き換える
  4. @EnvironmentObjectを@Environment(Library.self)に置き換える
  5. @ObservedObjectを外す。バインディングが必要なViewでは@Bindableに置き換える
// 移行前
class Book: ObservableObject, Identifiable {
    @Published var title = "Sample Book Title"
    let id = UUID()
}

// 移行後
@Observable class Book: Identifiable {
    var title = "Sample Book Title"
    let id = UUID()
}

手順1と2を終えた時点でも、アプリは従来どおりに動く。@StateObjectや@EnvironmentObjectは、@Observableを付けた型にも対応しているためである。移行ガイドも、一括ではなく型ごとに進める方法を勧めている。

Your app can mix data model types that use different observation systems.

出典: Migrating from the Observable Object protocol to the Observable macro[1]

バインディングが必要なViewでは、@Bindableを付けたプロパティから$でバインディングを取り出す。

struct BookEditView: View {
    @Bindable var book: Book

    var body: some View {
        TextField("Title", text: $book.title)
    }
}

注意点

移行中は、Viewが読むモデルの型によって更新条件が異なる。ObservableObjectのままの型を読むViewは、従来どおり読んでいないプロパティの変更でも更新される[1]。

@Publishedを外すと、$titleのようなPublisherは使えなくなる。Combineのパイプラインで値を購読している箇所は、Observationの仕組みへ書き換える。Swift 6.2以降では、Observationsで値の変化を非同期シーケンスとして受け取れる[2]。

iOS 16以前もサポートする場合

Perceptionライブラリは、@Observable、withObservationTracking、Observationsを、iOS 13、macOS 10.15、tvOS 13、watchOS 6まで使えるようにする[3]。

@Observableの代わりに@Perceptibleを付け、Viewのbodyの中身をWithPerceptionTrackingで囲む。この1点を除けば、使い方は公式のツールとほぼ同じである[3]。
