# マークダウンファイルの和訳

## ファイル命名規則

翻訳元ファイルのタイトルの先頭に`<JA>`を付けた名前で新規マークダウンファイルを作成する。

**例:** `Swift Documentation` → `<JA>Swift Documentation`

## フロントマターの扱い

翻訳元のフロントマター(YAML)から以下の項目を引き継ぐ:
- tags
- alias
- source
- created

さらに、翻訳後のファイルのtagsに`translatedToJA`と`Unread`を追加する。
逆に、翻訳元のファイルのtagsに`Unread`があれば、翻訳元ファイルのtagsから`Unread`を削除する。
こうすることで、翻訳後のファイルだけが未読であるとわかる。

最後に、和訳後とオリジナルのファイルのフロントマターに、以下をそれぞれ追加する。
- 和訳後のファイルのフロントマターに`translatedFrom: "[[オリジナルのファイルの名前]]"`
- オリジナルのファイルのフロントマターに`translatedToJA: "[[和訳後のファイルの名前]]"`

翻訳元ファイルの編集に許可が必要な場合は、編集が必要になった際に許可を求める。
「編集に許可が必要なので編集しなかった」という状態で作業を完了してはいけない。

## 翻訳の方針

- **内容を絶対に省略しない。** 原文のすべての情報を訳出する
- **常体(だ・である調)で翻訳する**
- **句読点は「、」と「。」を使う**
- **アルファベットの固有名詞はそのまま残す。** 無理にカタカナにしない
- **サブエージェントで分担して効率よく翻訳する**
- **`japanese-writing-rules`スキルの表記ルールに従う**

## 翻訳漏れの検証

翻訳完了後、原文ファイルと翻訳後ファイルの以下を比較して翻訳漏れがないか確認する:

| 項目 | 期待される結果 |
|------|----------------|
| セクション数 | 一致 |
| 行数 | 翻訳後のフロントマターが2行増加(タグ2個追加分)。それ以外は一致 |
| 画像リンクの数 | 一致 |
| コードブロックの数 | 一致 |

差異がある場合は翻訳漏れとして修正する。
