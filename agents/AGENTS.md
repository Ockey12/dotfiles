XcodeプロジェクトやSwift Package Managerのパッケージを扱う際は、以下の優先順位に従って。状況に当てはまる最初の選択肢を選び、リストを飛ばして下の項目へ進まないで。
1. Xcode MCP Tools: Xcodeでプロジェクトを開いている場合に使用する。起動中のXcodeのビルド状態を再利用するため、DerivedDataやビルドキャッシュが重複して蓄積されることがない。また、CLIでは不可能なワークフロー(起動中のIDEを介したスクリーンショットやスナップショットテストの実行、ユーザーが使用中のシミュレーターの操作など)を実現できる。
2. xcodebuildコマンド: CLIでのビルドやテストに使用する。バンドルされたリソース(.xcstringsの文字列カタログをロケールごとの.stringsに変換、.xcassetsのコンパイルなど)を正しく処理できる。Xcodeが開いていない場合や、ヘッドレス(UIのない環境)でのビルドが必要な場合に使用する。
3. swift build / swift testコマンド: 最後の手段。リソースを含まない純粋なSwiftパッケージの場合のみ安全に使用できる。これらのコマンドはバンドルされたリソースを解決できない。例えば、.xcstringsファイルはBundle.moduleにコピーされるだけで、ロケールごとの.stringsにコンパイルされない。そのため、実行時に `String(localized:bundle:)` を呼び出すと生のキーが返され、翻訳されたテキストを検証するテストはすべて失敗する。.xcassetsの画像検索でも同様の問題が発生する。パッケージで `resources: [.process("Resources")]` が宣言されており、単純なデータファイル以上のものが含まれている場合、`swift test` はリソースに依存するテストでエラーを警告することなく失敗する。その際は必ず `xcodebuild` を使用して。
